# ADR 0009: CASMI 実験ダッシュボードの継続更新

- Status: Proposed
- Date: 2026-11-05
- Updated: 2026-11-08（採点待ち点とローカルCVなしの提出の扱いを確認）
- Decision owners: Maintainers
- Supersedes: None
- Superseded by: None

## Context

CASMI のローカル評価と Kaggle Public LB の結果は別々の実験・提出台帳に蓄積される。静的ダッシュボードはいつでも参照できるが、結果を記録しただけでは自動更新されず、実際の最新結果と食い違う可能性がある。ローカル評価と LB は対象や測定精度も異なる。

2026-11-07 に採点が完了した JESTR 型、MIST 型、学習型フラグメントのローカル値は、共通の1,000分子・同分子式25候補の人工診断パネルで得たモデル単独 MRR@25 である。先行 FPNet 再学習の値は別の自然物ホールドアウトの固定候補評価であり、既存の80分子・145スペクトルの選択的既知構造パネルとも対象が異なる。これらを単一の散布図に置くと、横軸の大小を同条件の性能差と誤読しやすい。

## Decision

CASMI の実験または提出結果を変更したときは、台帳と `strategy/dashboard-curated.json` の必要な根拠付き情報を更新し、`site-dashboard/` の生成・検証手順に従って集計し、既存サイトへ再デプロイする。ユーザーの明示指示により、サイトのアクセス範囲は一般公開とし、認証なしでスマートフォンからも閲覧できる表示にする。ローカル評価を横軸、Public LB を縦軸とし、対応する観測だけを比較する。未完了・未取得・異なる評価条件の結果を確定済みや直接比較可能として扱わない。更新日時と評価上の制約を明示する。

ダッシュボードには集計・実験履歴だけを載せ、生データ、予測、提出ファイル、API キー、一時的なデプロイ資格情報、個人情報を入れない。ローカル生成・検証と外部サービスへのデプロイは別段階であり、成功が確認できない場合は更新未反映として報告する。新規サイトを作り直さず、既存の Sites プロジェクトを使う。アクセス設定を `public` に変更した後は、その状態を再確認してから公開版をデプロイする。以後のアクセス範囲変更はユーザーの明示指示を必要とする。

「各実験のスコア」には採点済みの学習モデルも示す。ただし評価条件ごとにプロットを分け、同じローカル軸に異なる母集団の MRR を重ねない。80分子パネルは従来の比較を維持し、同じ1,000分子・同式25候補で評価した JESTR、MIST の学習条件別モデル、学習型フラグメントなどは共通パネルの比較群、FPNet は自然物ホールドアウトの別群として示す。各点は `experiment_id`・`split_id` と Kaggle `submission_ref` を明示して対応する台帳記録に結び付け、異なる候補集合や単独モデルと親パイプラインの違いを注記する。Public LB は小数第3位の表示値であり、差の統計的有意性や未知分子への一般化を示さない。全群を一つの散布図に重ねる案は評価母集団を混同させるため採用しない。

同じ評価群の学習条件比較でも、Public LB の3桁表示が同点なら複数の点が重なることを図と一覧で示す。ローカル単独MRRの差だけで提出経路の改善を主張せず、難候補の有無や学習ステップを変えた実験は提出IDを分けて追跡する。表示値が0.001異なる場合も、各1提出から統計的有意性を判断しない。

## Consequences

結果更新時に追加の生成、検証、デプロイが必要になるが、結果の根拠と画面の対応を追跡できる。静的サイトは自動同期されないため、実行環境や認証の問題でデプロイできなかった場合、閲覧中のページは古いままになる。一般公開により誰でも URL から集計を閲覧できるため、公開前のデータ最小化とモバイル表示確認が必要になる。
評価群を分けるため図は増えるが、同じ座標上での見かけ上の順位比較を避けられる。FPNet の単独点から群内相関や最適な閾値は推定しない。

## Validation

更新手順に用いるハーネスで入力と出力の整合性を検証し、集計以外のデータが生成物に混入していないこと、狭い画面幅で表やグラフを閲覧できること、`get_site` の `access_mode` が `public` であること、最終デプロイ状態を確認する。検証やデプロイが未実施・失敗の場合は成功と記録しない。図示上の相関は評価集団の違いと選択バイアスを踏まえ、断定しない。
追加した各点について、表示のローカル値と `split_id` を `cv-results.jsonl`、公開値・提出ID・COMPLETE 状態を `lb-submissions.jsonl` と照合する。共通1,000分子パネルの学習モデル群と自然物ホールドアウトのFPNet点が別群に描かれ、公開される JSON・JavaScript・HTML に生データや資格情報がないことを確認する。点数が増えた場合は、図中の番号と下の一覧の対応、近接点の重なりも確認する。

## 2026-11-08 の適用確認

EXP-0030の固定1,000分子・同式25候補パネルのモデル単独MRR@25は0.567918。提出58121189のPublic LBは0.477で確定した。共通パネル群の点はローカル値と公開値を別軸で表示し、公式データのみ12,000ステップ版の0.479との差を単一提出・3桁表示の観測差として扱う。EXP-0027の同じパネルのモデル単独MRR@25は0.503482、提出58112257のPublic LBは0.478で確定した。二つの軸の評価対象は異なる。

EXP-0028の公開Notebook再現は提出58114319のPublic LB 0.481が確定したが、同条件のローカルCVを実施していない。履歴と提出表には表示し、ローカル値を推測して散布図に配置しない。公開サイトでは提出IDを公開用の別名で表し、ローカル台帳で実IDとの対応を保持する。結果を更新したときは、この別名対応と、実IDやローカルファイルパスが公開JSONに混入していないことを検査する。EXP-0031の提出はEXP-0028とCSVがバイト一致し、モデル追加の効果を示す点として追加しない。
