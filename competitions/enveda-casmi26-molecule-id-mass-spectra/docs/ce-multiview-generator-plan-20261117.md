# CE別スペクトルを使う候補生成の比較計画（2026-11-17）

## 目的と対照

MS/MS Mixupの5提出は、固定候補を再順位付けする0.479条件を表示上超えなかった。次は候補生成の手前で20/40/60 eVの実測スペクトルを別視点として扱い、正解構造が候補に入るかを検証する。0.477親Notebookの候補生成は、類似スペクトルから既知アナログを選び、質量差に合う誘導体を規則で列挙する。学習型生成器ではない。親の `EngineCfg.analog_query` の既定値 `merged` は同極性スペクトルを検索前に統合する。`each` は各実測スペクトルを別々に検索し、同一アナログの最大スコアを取る。最初の変更はこの1点に限定する。

主対照は保存済み0.477親Notebook（候補集合を固定しない）。既存0.479のMIST再順位付けは二次比較とし、生成段階の効果を測る初回条件へは混ぜない。

## 段階的な条件

1. **G0**: 親の `analog_query='merged'`。保存済み0.477対照と同じ出力・入力hashを照合する。
2. **G1**: `analog_query='each'` のみ変更する。訓練済み重み、参照スペクトル、pool、生成規則、採点器のコードと重み、後処理を固定する。入力にある20/40/60 eVの単独測定と複数CE統合行を、それぞれ検索クエリーにする。統合行が独立した測定か計算統合かは未確認なので、独立した教師とは数えない。ただし `Engine.run` は同じアナログ検索結果を候補生成と順位用のアナログ特徴量の両方へ使う。したがってG1のMRR/LB差を生成だけに帰属しない。
3. **G2（準備済み）**: 通常の `merged` 検索を順位特徴量に残し、規則生成の親選択だけを別視点 `each` で再検索する。G1の候補生成とアナログ順位特徴量を分ける対照とする。
4. **G3（準備済み）**: G2に同一クエリー分子・同一アダクト・極性・装置で隣接する単一20/40/60 eV測定の穏やかなピークMixupを追加する。主スペクトル比0.85～0.95、前駆体差20 ppm以内、複数CE統合行はペアに使わない。生成親の検索クエリーだけに合成viewを足し、順位特徴量はG2と同じ元 `merged` 検索を使う。G3−G2がMixup追加の比較となる。
5. G1の分子別結果とPublic LBを確認後、準備済みのG2/G3を含め、残り最大4枠から実際の提出順と後続条件を選ぶ。別構造の合成スペクトルに単一SMILESを教師として与えない。追加条件の決定を提出前に記録する。

## ローカル評価と監査

- 同じ0.477親ソース・入力・候補poolを使い、変更したセルとSHA-256を保存する。ラベルは推論が完了するまでNotebook側へ渡さない。
- 分子非重複のEnveda-180保留分子と、保存済みのラベル付き外部80分子代理パネルを別々に評価する。Enveda保留分子はMIST学習から外れていても、0.477親の参照ライブラリと候補poolには含まれ得る。検証時に自己参照スペクトル・自己pool構造を除外し、除外できない行は未見構造の評価と呼ばない。外部代理パネルは80分子・145スペクトルで、20 eV 49件、40 eV 43件、60 eV 24件、20/40/60 eV統合測定29件を含む。代表性を仮定せず、親の参照・poolとの構造重複を別途監査する。
- **候補生成**: pool由来と規則生成由来を分け、正解InChIKey14の全候補内・Top25内の包含率、追加・喪失、生成候補だけが救済した件数を記録する。
- **順位**: 候補内での正解順位、Top1、MRR@25、候補がない群の割合を記録する。候補集合を固定した旧Mixup評価のMRRと直接比較しない。
- 可視テストNotebookの出力では、sample ID順、400行、SMILESの重複・欠損・個数、変更セル、親ソース、推論エラー、生成候補数を確認する。可視行の変化を隠しテスト精度とみなさない。

## 提出と更新

ユーザーは本サイクルで最大5枠を許可した。まずG1のローカル評価とNotebook完了出力を確認して1本提出し、採点結果から次の変更を選ぶ。各条件のNotebook、候補pool、モデル、提出CSVのhash、Public LBの値、分子別ローカル差を実験台帳に記録する。競技ルールの提出上限と当日残枠をKaggle APIで提出前に確認する。ダッシュボードは確定したローカル・Public LBの値を分けて更新する。
