# Current Strategy: Enveda CASMI 2026 - Molecule ID From Mass Spectra

## Competition Contract

- 指標: MRR@25、最大化。SMILES を順位順にセミコロン区切りで最大 25 件出力する。
- 照合: RDKit 2026.03.3 の tautomer canonicalization と InChIKey の先頭 14 文字。
- Notebook 提出、`submission.csv`、CPU / GPU 最大 9 時間、インターネット無効。
- 公式情報と未確認事項は [概要](../docs/overview/README.md) と [設定](../competition.toml) に記録する。

## Working Hypothesis

まず、公式評価と提出形式に沿った候補生成・順位付けの最小ベースラインを構築し、
検証データで MRR@25 と候補のカバレッジを測る。データを未確認のため、モデル、
特徴量、分割方法の選択は保留する。

EXP-0009 では全11ソースを分子非重複で約9:1に分け、既知構造参照を別ソースに
許す条件と、正解候補のない群を同じ母数で評価した。RT・CCS・溶媒の各単独追加と
同分子式内の順位補正は、この設定では基準の分子均等 MRR を改善しなかった。
参照に検証分子の別ソース測定を含み、全く未知の構造の性能ではない。
詳細は [実験記録](experiments.md) と
[全ソース結果](../src/metadata_prediction/all-source-validation-results.md) を参照。

EXP-0010 の公開モデル無改変版は Public LB 0.477、RT・CCS・溶媒の推定差で
同分子式の隣接候補を補正した版は 0.473。旧 ektarr 検索での分子非重複CVも悪化し、
現設定の追加版は採用しない。両者とも各１提出で、差の個別要因は不明。
詳細は [実験記録](experiments.md) と

## Validation Plan

1. 公式ファイルと sample submission の schema を確認し、行と ID の対応を固定する。
2. 評価手順と RDKit のバージョン・正規化の詳細を確認して、小さな合成例で検証する。
3. リークを防ぎ test 分布を反映する分割単位をデータ調査後に決める。
4. 学習・推論の前に最小例で候補の順位、出力形式、重複と無効値を確認する。
5. 各実験で設定、seed、分割、データ版、commit、結果を `experiments.md` に残す。

ライブラリ間の化合物重複は集計済み。検証方針案と集計の根拠は [ADR 0005](../../../../docs/adr/0005-casmi-cross-library-validation.md) を参照。公開ベースラインと RT・CCS・溶媒推定値の追加比較は EXP-0007 に記録。Public LB は基準 0.155、RT 0.155、CCS 0.155、溶媒 0.156、併用 0.155。溶媒モデルは MassBank の２分類代理であり、実測条件の復元ではない。

## 2026-11-07 MIST 学習時間・難候補実験

前回の MIST 型は 6,000 ステップ、同式の学習用誤候補を毎回 1 件ランダムに選び
（同式候補がなければ別式から 1 件を補充）、
共通 1,000 分子・同式 25 候補パネルで単独 MRR@25 0.301177、Public LB 0.478
だった。学習時間の影響を見るため、同じ seed・分割・損失のまま 12,000 と

難候補の影響は 6,000 ステップに固定し、(A) ランダム 8 件、
(B) ランダム 4 件＋難候補 4 件、(C) ランダム 4 件＋難候補 8 件を比較する。
主要な対照は総負例数を 8 件に揃えた A と B とし、C は総数も 12 件に増える探索条件とする。
難候補は現在のモデルで正解と取り違えやすい同式構造から選ぶ。探索対象は学習 split
内の分子だけとし、正解と構造重複する候補と選択済みの候補を除く。同式候補が不足する場合は
重複や別式候補で埋めず、利用可能な件数を記録する。ランダム候補を残して難例への偏りを抑える。

5 件とも同じ親 Notebook・候補集合・1 位保護の提出経路で比較する。ローカル単独
MRR@25 と Public LB は評価対象が異なるため別々に記録する。Public LB の表示値が
前回 MIST の 0.478 を上回るかを主な判断材料とし、同点は丸め精度では改善の証拠としない。
提出前に schema、候補集合、ID 順、実際の候補順の変化を検査し、採点後に台帳と公開
ダッシュボードを更新する。

### 0.479を基準にした次の検証

1. EXP-0025の公式trainのみ12,000更新checkpointと0.477親Notebook、同式内RRF重み0.25、1位保護を固定基準にする。EXP-0026の18,000更新もPublic LB表示値0.479で同点のため、より短い12,000更新版を基準にする。
2. 次の第一候補は学習を増やす案ではなく融合の強度・適用条件の調整。重み0、0.10、0.25と、同式群のサイズや親順位とMIST順位の食い違いによる選択適用を同じ候補集合上で比較する。1位保護は維持して主比較を単純にする。
3. 既存の人工同式25候補MRRを採用判定には単独で使わない。親Notebookの候補生成・複数スペクトル集約・順位融合まで再現し、検証分子が親およびMISTの学習に混入しない分子非重複評価を用意する。公開可視12分子の候補順変更は正解ラベルがないため採用判定に使わない。
4. 同じ親CSV、同じ提出経路、同じ検証条件を維持して一度に一要因を変え、ローカルで悪化しない案だけをKaggleの残り提出枠へ進める。Public LBの3桁表示・単一提出から効果の有意性は断定しない。

## 2026-11-17 CE別視点を候補生成に適用

最初の仮説G1は、0.477親のアナログ検索を同極性のスペクトル統合 `merged` から実測スペクトル別 `each` に変えると、20/40/60 eVに固有の断片を利用でき、正解候補包含率またはPublic LBが改善する、というもの。FPNet、候補pool、誘導体生成規則、採点器のコードと重み、後処理を固定し、候補集合は固定しない。同じ検索結果が順位用のアナログ特徴量にも入るため、MRR/LB差は生成だけの効果ではない。ローカルでは分子非重複Enveda保留と外部80分子の正解包含率・MRR@25を分けて測る。対照は0.477親のPublic LB 0.477で、既存MIST再順位付けの0.479とは別の比較とする。G1の結果後に残りの提出条件を決める。条件と監査は `docs/ce-multiview-generator-plan-20261117.md`。

G2は生成親だけを各CEで検索し、アナログ順位特徴量を元の `merged` に固定する。G3はG2の生成検索に、同一分子・アダクト・装置の隣接する単一CE測定を主比率0.85～0.95で混ぜたクエリーviewを加える。元の複数CE統合行はMixupの相手にしない。両条件のprivate Notebookを準備し、G1のローカル全工程とPublic LBを見て競技提出を選ぶ。
