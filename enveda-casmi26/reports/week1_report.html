やったこと

4 段階で進めた

  1. 誤差分解ツールを実装候補 pool → FP 予測 → シミュレータ → ランカーの任意の段構成に対応。テスト 11 件。
  2. EXP-0001：fold-safe baseline を 4 条件で実行検証 split は NP ホールドアウト（250 分子、hidden test に最も近い）と identity fold 0（400 分子）。ホールドアウト構造を候補 pool に残す（keep）か除く（drop）かの 2 通り。ライブラリからはホールドアウト構造のスペクトルをすべて除いた。
  3. LB に 2 本提出：A 固定融合 / B analog 単独CV で差が +0.34 ある 2 本を選び、結果を見る前に判定基準（±0.03）を README に固定した。
  4. EXP-0002：Class 1 を模した CV と、クラス構成の逆算他ソースの reference スペクトルを残した CV でクラス別 MRR を実測し、2 本の LB と連立して hidden test のクラス構成を解いた。

keep 条件では pool のカバー率は 99.6–100% で、候補窓（中央値 53–88 件）に正解はほぼ入っている。drop 条件で pool 段の損失がほぼ 100% になるのは、手元の COCONUT データが train 構造を除いた版（重複 0 件）だからで、データセットの作りに由来する最悪ケース。

単一チャネル vs 固定融合（keep 条件）

融合（A）は analog 単独（B）よりはるかに悪い。CV では正解の reference が必ず除かれるので、ライブラリ一致は常に別の異性体を指す。94–99% の分子に一致があり、融合の 1 位の 66–76% がそれに引っ張られた。

残っている小さな宿題

  • Overview の Code Requirements（推論時間制限）とチーム合併締切の確認。今回の kernel は CPU で約 28 分
  • RDKit の版差テスト（ローカル 2026.09.1 と公式 2026.03.3）。Kaggle 上では 2026.03.3 で動作確認済み
  • breakdown.py の lint / 型エラー。指標ハッシュの freeze 対象なので、直すときは metric_hash.txt を同時に更新する
この報告の限界

クラス構成の推定は、ちょうど解けてしまう連立方程式に乗っている

  • 未知数 2 つに式 2 本なので、モデルが正しいかどうかの検定にはならない。次の提出で予測 LB を書き、外れるかで反証する
  • CV のクラス別 MRR が hidden test でも成り立つことを前提にしている。NP ホールドアウトは最も近い proxy だが、同じ分布とは限らない
  • ここでの「pool 外」は「COCONUT ∪ train 構造にない」という意味で、Discussion でいう Class 3（完全な新規化合物）とは別物。PubChem には入っている分子が多いはず
  • 固定融合の重み（lib + analog + 0.25 frag）は手で決めた値で、検証データで調整していない
